# CapCut 장면 컷 나누기 (SceneCut)

장면이 바뀌는 지점을 자동으로 찾아, **CapCut 프로젝트의 영상을 그 자리에서 쪼개는** 로컬 웹앱.
직접 손으로 수십 번 자르던 것을 한 번에 한다.

```
run.bat            (또는  python run.py)
```

브라우저가 열리면 프로젝트 고르기 → 조각 고르기 → 분석 → 민감도 → 검수 → 적용 순으로 진행한다.

## 받아서 쓰기

[Releases](../../releases) 에서 exe 를 받아 **쓰기 가능한 폴더**(바탕화면, 문서 등)에 두고
더블클릭한다. `Program Files` 안에 두면 ffmpeg 자동 설치가 권한 때문에 실패한다.

### "Windows의 PC 보호" 경고가 뜬다면

코드 서명 인증서가 없어서 뜨는 경고다. 인증서는 개인이 사기에는 비싸다.
**추가 정보** → **실행** 을 누르면 된다.

백신이 잡는 경우도 있는데 PyInstaller 로 묶은 프로그램의 흔한 오탐이다. 파이썬 해석기와
스크립트가 한 파일에 압축돼 있는 모양새가 악성코드 포장과 비슷해서 그렇다. 마음이 놓이지
않으면 소스를 직접 받아 `python run.py` 로 돌리거나, `python build_exe.py` 로 직접 묶으면 된다.
하는 일은 전부 이 저장소 안에 있고, 서드파티 패키지를 하나도 쓰지 않는다.

## 필요한 것

- **CapCut International** (`platform.app_source == "cc"`) 6.x ~ 9.x
- **ffmpeg / ffprobe** — 없으면 앱이 첫 화면에서 자동 설치를 권한다 (아래)
- Python 3.10+ (실행 파일로 묶으면 필요 없다)

파이썬 서드파티 패키지는 **하나도 쓰지 않는다.**

### ffmpeg 자동 설치

ffmpeg 가 없으면 첫 화면 위에 배너가 뜨고, 버튼 하나로 받아 설치한다. 받는 곳은 gyan.dev
(ffmpeg.org 가 윈도우 공식 빌드로 링크하는 곳)이고, 배포처가 올려둔 **SHA-256 을 대조해서**
받은 파일이 온전한지 확인한 뒤 `bin/` 에 푼다.

- essentials 빌드를 쓴다. full 빌드는 두 배 넘게 큰데 여기서 쓰는 것은 `scdet` 필터와
  mjpeg 인코더뿐이다. 내려받기 111MB, 설치 뒤 `bin/` 은 약 206MB (ffmpeg + ffprobe).
- 압축 안 경로를 그대로 쓰지 않고 **파일 이름만** 보고 `bin/` 바로 아래에 쓴다. 압축이
  `../` 같은 경로를 담고 있어도 바깥으로 새어나가지 못하게 하려는 것이다.
- 설치 뒤 `scdet` 필터가 실제로 있는지 확인한다. 이 확인이 없으면 scdet 없는 빌드를 받았을 때
  설치는 성공했다고 나오고 정작 분석할 때 알 수 없는 오류가 난다.

찾는 순서는 `bin/` → exe 안에 묶인 것 → PATH 다. `bin/` 을 먼저 보는 이유는 PATH 의 ffmpeg 가
`scdet` 없는 오래된 빌드일 수 있기 때문이다.

> **PyInstaller 주의**: `bin/` 은 `sys._MEIPASS` 가 아니라 **실행 파일 자신이 있는 폴더** 기준이다.
> `_MEIPASS` 는 실행할 때마다 새로 만들어졌다가 끝나면 지워지는 임시 폴더라, 거기에 받아두면
> 다음 실행에 사라진다.

## 왜 웹 호스팅이 아니라 로컬인가

Chromium 이 File System Access API 에서 `LOCAL_APP_DATA` 아래를 하위까지 통째로 막는데
(`kBlockAllChildren`), CapCut 드래프트가 정확히 그 안에 있다. 브라우저만으로는 접근할 수 없다.
게다가 영상은 GB 단위라 클라우드로 올리는 것 자체가 병목이다. 로컬 서버 + 브라우저 UI 가
유일하게 말이 되는 구조다.

127.0.0.1 에만 바인딩하고, 시작할 때 만든 토큰을 모든 요청에 요구한다.

## 어떻게 장면을 찾나

`ffmpeg` 의 `scdet` 필터를 **임계값 0** 으로 돌려 모든 프레임의 장면 변화 점수를 받아온 뒤,
컷 판정은 파이썬에서 한다. 두 단계를 나눈 것이 이 도구의 핵심이다.

- **임계값을 바꿔도 영상을 다시 읽지 않는다.** 점수 곡선을 들고 있으므로 슬라이더를 움직이면
  즉시 컷 수가 바뀐다. ffmpeg 에 임계값을 맡겼다면 매번 몇 초씩 다시 스캔해야 한다.
- **주변 프레임과 비교해서 판정한다.** 카메라가 계속 패닝하는 구간은 점수가 통째로 높아서
  절대값만 보면 온통 컷이 된다. 주변 평균의 몇 배인지를 같이 본다.
- **임계값 초깃값은 Otsu 이진화로 고른다.** 컷 프레임은 전체의 몇 퍼센트뿐이라 점수 분포가
  두 덩어리로 갈리는데, 그 사이 골짜기를 찾는다. 백분위수로 자르는 방식은 컷 비율을 미리
  안다고 가정하는 셈이라 영상마다 다른 방향으로 빗나간다.

PySceneDetect 를 쓰지 않은 이유는 opencv 와 numpy 를 끌고 오기 때문이다. 실행 파일이 수십 MB
불어나는데, ffmpeg 는 어차피 있어야 한다.

실측 (1080×1920, 234 초, 7028 프레임): 전체 스캔 **5.4 초**, 임계값 재판정 **0.00 초**,
썸네일 컷당 0.10 초.

### 가변 프레임레이트(VFR)

폰 촬영본과 화면 녹화는 명목 fps 와 실제 프레임 간격이 다르다. `프레임 번호 / fps` 로 시각을
계산하면 뒤로 갈수록 밀린다. 이 도구는 컷 위치에 **ffmpeg 이 알려준 실제 pts 를 그대로 쓰므로**
VFR 이어도 어긋나지 않는다. 감지되면 화면에 알려준다.

## 어떻게 CapCut 을 고치나

`draft_content.json` 을 직접 고쳐 쓴다. CapCut 이 손으로 분할할 때 하는 일을 그대로 흉내내는데,
실제로 한 영상을 88 조각으로 나눈 프로젝트를 뜯어보고 확인한 규칙이다.

- 조각마다 영상 material 을 **통째로 복제**한다. 88 개 복제본을 비교하면 서로 다른 필드는
  `id` 하나뿐이다. `path` 도 `duration` 도 `material_id` 도 전부 같다. 즉 복제본의 `duration` 은
  여전히 원본 파일 전체 길이이고, 실제로 쓰는 구간은 세그먼트의 `source_timerange` 가 정한다.
- 세그먼트마다 부속 material **6 종**(`speeds`, `placeholder_infos`, `canvases`,
  `sound_channel_mappings`, `material_colors`, `vocal_separations`)을 각자 하나씩 갖는다.
  공유하지 않는다. 빠지면 CapCut 이 소재를 인식하지 못한다.
- 시간 단위는 전부 **마이크로초**.
- **배속이 걸린 조각**은 원본 1 초가 타임라인에서 1 초가 아니다. `speed` 로 나눠서 옮긴다.
  마지막 경계는 반올림 오차가 끼지 않게 원래 끝값을 그대로 써서, 조각 길이의 합이 원래 길이와
  정확히 같아지게 한다.

나누기만 하고 늘이거나 줄이지 않으므로 **오디오·자막 트랙은 건드리지 않는다.**

### 안전장치

- 저장 전에 `check_draft.verify()` 가 겹침·빈틈·길이 0 조각·소재 유실·id 중복·전체 길이 변화를
  검사한다. 하나라도 걸리면 **저장하지 않는다.** CapCut 은 어긋난 드래프트를 열어도 오류를 내지
  않고 조용히 이상하게 그리기 때문에, 여기서 막지 못하면 원인을 알 수 없게 된다.
- 적용할 때마다 `*.scenecut-backup.json` 백업을 만들고, 화면에서 되돌릴 수 있다.
- 임시 파일에 먼저 쓰고 바꿔치기하므로, 쓰는 도중 문제가 생겨도 원본이 반쯤 덮이지 않는다.

### 한계

- **키프레임이 걸린 조각은 건너뛴다.** 키프레임은 세그먼트 안에서의 상대 시각으로 저장되는데,
  쪼개면서 잘못 옮기면 확대/이동 애니메이션이 조용히 어긋난다. 손대지 않고 알려준다.
- 剪映(JianYing) 6.0+ 는 저장할 때마다 드래프트를 암호화해서 지원할 수 없다.
- **CapCut 을 완전히 닫고** 적용해야 한다. 열려 있으면 CapCut 이 기억하던 내용으로 덮어쓴다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `run.py` | 진입점. 서버를 띄우고 브라우저를 연다 |
| `server.py` | 로컬 HTTP 서버와 JSON API |
| `jobs.py` | 오래 걸리는 작업을 백그라운드로 돌리고 진행률을 알려준다 |
| `media.py` | ffprobe 로 영상 정보를 읽는다. VFR 감지 |
| `detect.py` | scdet 점수 곡선 + Otsu 임계값 + 컷 판정 |
| `capcut_draft.py` | 드래프트 읽기 / 백업 / 저장 |
| `splitter.py` | 세그먼트를 실제로 쪼갠다 |
| `check_draft.py` | 저장 직전 무결성 검사 |
| `thumbs.py` | 컷 전 / 후 썸네일 |
| `folder_picker.py` | 네이티브 폴더 선택 창 |
| `web/` | 화면 (바닐라 JS) |

`capcut_matcher` 에서 `folder_picker.py` 와 `capcut_draft.py` 의 뼈대를 가져왔다.

### PyInstaller 주의

묶으면 `sys.executable` 이 python.exe 가 아니라 **실행 파일 자신**이다. 자식 프로세스를
`[sys.executable, "스크립트.py", ...]` 로 띄우면 앱이 통째로 다시 켜진다. 그래서 `run.py` 가
서버를 띄우기 **전에** `--pick-path` 플래그를 먼저 확인한다. 소스로 돌릴 땐 멀쩡해서 놓치기 쉽다.
